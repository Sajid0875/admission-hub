Partner Portal Frontend
Implementation Plan
Phased build plan + copy-paste prompts for each phase

Scope: Frontend only - React / Next.js + Tailwind CSS, with React Query and a small client-state store.
Source basis: WhiteDavid23 Multi-Tenant Partner Portal HLD/LLD v1.0 (6 pages).

Core business flow
Login -> Dashboard -> Leads -> Follow-up / Demo -> Admitted or Lost -> Admission -> Commission -> Payout

The prompts are deliberately scoped so a coding agent works on only one phase at a time instead of
regenerating the whole frontend.

Project rules for every phase
These rules keep the frontend aligned with the handover document and prevent frontend code from
taking over backend responsibilities.


Frontend only. Do not change Express, MongoDB, Mongoose, Redis, middleware, commission
rules, duplicate-detection rules, or other backend logic.



Use React / Next.js + Tailwind CSS. Use React Query for server state. Use Zustand (or the existing
Redux Toolkit setup if the project already uses it) only for small global client/UI state.



Keep API access inside a dedicated service layer. React components must not talk to MongoDB or
storage directly.



Treat roles and permissions as UI behavior only. The frontend may hide unavailable actions, but
the backend remains the security authority.



Never hardcode tenant isolation in the UI. The backend is responsible for server-side partnerId
scoping.



Only integrate endpoints that actually exist. If the handover does not define an endpoint needed
for a screen, create a typed service placeholder / mock adapter and clearly mark it TODO instead
of inventing a backend contract.



For every API-driven screen include loading, empty, success, validation, unauthorized (401),
forbidden (403), duplicate (409 where relevant), and generic error states.



Keep the UI responsive for desktop and mobile, keyboard accessible, and reusable. Avoid one huge
page component.



At the end of each phase, report: files created/changed, routes added, API contracts used,
mock/TODO contracts, and a short manual test checklist.



Do not start the next phase automatically. Stop after this phase is complete.

Appendix B - Source-derived frontend boundaries


The architecture is multi-tenant by partnerId; Super Admin has cross-tenant visibility while
partner users are scoped to their own tenant.



Server-side tenant scoping is a design goal; it must not rely on hiding data in the UI.



The documented frontend technology is React (Next.js) + Tailwind CSS, with Redux Toolkit /
Zustand and React Query.



The backend is Node.js + Express.js, data is MongoDB Atlas via Mongoose, cache is Redis, and file
storage is S3/Cloudinary. The frontend should consume REST APIs rather than access these data
services directly.
